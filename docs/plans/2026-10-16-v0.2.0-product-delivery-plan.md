# v0.2.0 个人效率 Hub 实施计划

> status: active
> target: `0.2.0`
> paired PRD: `docs/PRD-v0.2.0.md`
> owner: EasyFlowHub maintainers

## 1. 交付策略

v0.2.0 以一条可重复使用的个人效率链路为验收单位：

`当前上下文 -> Launcher / 中键 -> 捕获或处理 -> Inbox / 剪贴板 / 文件 -> Manager 整理`

先稳定输入、输出、附件和失败反馈，再在这些基础上接入文件、下载和语音能力。每个 Phase 都要保留可运行的 Windows 主路径，不把所有功能堆到最后一次集成。

## 2. 阶段拆解

| Phase | 目标 | 交付范围 | 状态 | Gate |
|---|---|---|---|---|
| 0. Foundation | 统一契约和视觉基础 | action context、attachment / Inbox 模型、权限与失败反馈、design tokens | in_progress | F0 |
| 1. Capture | 让用户快速收集内容 | Snow Shot 会话入口、剪贴板 / 文本 / 链接 / 图片 / 文件捕获、Inbox、整理为笔记 | in_progress | F1 |
| 2. Understand | 让捕获内容可立即理解 | 选中文本翻译、剪贴板翻译、Provider adapter、输出回流 | in_progress | F2 |
| 3. Retrieve | 找到并处理本地资源 | 指定目录索引、文件搜索 / 预览 / 操作 | in_progress | F3 |
| 4. Download | 收口资源获取链路 | URL 队列、进度、暂停 / 继续 / 重试、结果动作 | in_progress | F4 |
| 5. Voice | 将声音纳入 Inbox | Windows 录音、音频附件和原件回流；录音后转写（Relay Provider + 隐私确认） | in_progress | F5 |
| 6. Glass Theme | 统一桌面工作空间视觉 | token 迁移、fallback、状态、可读性和性能验证 | in_progress | F6 |

视觉主题从 Phase 0 开始建立，Phase 6 完成跨页面迁移；它不是最后才开始的纯美化工作。

## 3. Phase 0：Foundation

### 目标

为所有后续动作提供稳定的输入、输出、附件和反馈约定，并确保全局入口不会干扰专注软件。

### 任务

- 扩展 action registry：上下文输入、输出路由、取消、失败和来源字段。
- 建立 `Capture`、`Attachment`、`InboxItem`、`ActionResult` 数据模型；先保持本地 SQLite / 文件系统 owner 清晰。
- 把剪贴板、选中文本、当前文件、截图、当前窗口抽象为可检测的上下文快照。
- 为外部应用动作建立统一检测 / 启动 wrapper；Snow Shot 的用户自定义路径优先，随后检查 Windows 已安装应用注册信息、常见安装目录和 PATH。
- 保留键盘、中键、键盘 + 中键三种触发策略；加入排除进程和快捷键冲突反馈。
- 建立设计 token 和明亮玻璃主题的基础变量，提供关闭模糊时的不透明 fallback。
- 记录 Windows 权限、Provider 不可用、快捷键占用和输入缺失的可理解错误。

### 依赖与验收

- 复用现有 `easyflowhub-app/src/features/actions`、`src/features/launcher` 和 `src/lib/tauri/launcher.ts`。
- 不让新的动作页面直接调用 Tauri `invoke()`；所有跨层调用进入既有 wrapper owner。
- Gate F0：现有 Launcher 回归通过，新增契约有类型测试，Manager / Launcher / Quick Note 至少能读取同一套 token。

## 4. Phase 1：Capture

### 任务

- 截图首版通过内置 `external.snow-shot.capture` 动作调用 Snow Shot 官方 MCP bridge；EasyFlowHub 负责 Launcher 入口、安装发现、MCP 状态检查和错误反馈，不捆绑或复制 Snow Shot。
- 已安装时启动相邻的 `snow-shot-mcp` bridge（`--launch-app`），完成 MCP 初始化后调用 `snow_shot_screenshot_begin` 进入可见截图界面；未安装时打开 <https://snowshot.top/download.html?os=windows>。
- Snow Shot 的 MCP integration 默认关闭，用户需在「设置 → 系统」开启。MCP 未启用显示设置指引；已安装但 bridge 缺失或版本不支持时提示更新，不误判为未安装。
- 程序发现顺序为用户自定义路径、Windows 卸载注册信息（覆盖 D 盘及其他非系统盘）、常见目录、PATH。自定义无效路径应报错，不静默回退到另一个可执行文件。
- 全屏、窗口、区域和矩形 / 箭头 / 文字 / 马赛克标注由 Snow Shot 提供；不模拟 Snow Shot 用户快捷键，也不依赖未经确认的命令行截图参数或由 EasyFlowHub 注册 Snow Shot 快捷键。
- EasyFlowHub 仍保留统一 `image` 附件和 Inbox 回流接口；自动结果回流、OCR 和翻译联动不属于本阶段截图动作完成条件。
- Launcher 提供一键收集剪贴板内容（优先图片、回退文本）；Manager 的 Notes 面板内提供“收集箱 / 笔记”切换，不增加侧栏顶层模块。
- 收集箱入口支持纯文本、URL、剪贴板图片和本地文件选择 / 拖放，不强制分类；保存时记录时间、入口来源和捕获上下文。
- Inbox 支持按时间浏览、搜索、打开链接 / 附件、归档和恢复，并可事务性整理为笔记；图片继续使用现有 `asset:<uuid>` Markdown 引用。
- 新附件使用随机文件名、元数据表与独立于正文的存储关系；普通归档不清理文件，避免与现有笔记图片引用和回收站生命周期冲突。

### Gate F1

- 中键唤起 -> 点击 Snow Shot -> Snow Shot 可见截图界面打开；用户在 Snow Shot 复制后，可粘贴图片到 Inbox。自动截图结果回流不作为 Gate F1 条件。
- Launcher 的“收集剪贴板内容”动作可保存当前剪贴板图片或文本；Inbox 手动文本、URL、图片粘贴、文件选择 / 拖放均可写入并在列表中重开。
- Inbox 项可归档、恢复、打开附件 / 链接，并可幂等地整理为笔记；旧笔记 schema 和 `asset:` 图片引用保持可读。
- Windows 打包产物中，Snow Shot 已安装且 MCP 开启时进入截图界面；MCP 未开启时提示「设置 → 系统 → MCP integration」；未安装跳转官方安装页；自定义路径优先于注册表自动发现；D 盘注册安装能被发现。
- 无效自定义路径、bridge 缺失 / 版本不支持、权限不足和启动失败均有可理解反馈，已安装但 MCP 未配置时不跳转安装页。
- 关闭 Quick Note 或 Launcher 不会删除已保存的图片附件和 Inbox 项。
- MCP 不可用、截图工具调用失败和超时都有明确反馈；截图取消与保存由 Snow Shot 自身管理，EasyFlowHub 不重复覆盖其内部标注和保存实现。

## 5. Phase 2：Understand

### 任务

- 设计 Translation Provider interface：检测语言、翻译、取消、错误分类和配额提示。
- 支持选中文本与剪贴板文本，目标语言在设置中配置。
- 结果面板提供复制、替换选中文本（需用户触发）和写入 Inbox 三种出口。
- 为截图 OCR 预留输入类型和输出结构，但不把 OCR 质量作为 v0.2.0 硬门槛。

### 首条切片与已确认决策（2026-10-17）

- 首个 Provider 复用现有本机 ScriptMgr Relay，默认运行地址为 `http://localhost:8787`，请求接口为 `/v1/chat/completions`。EasyFlowHub 不增加密钥配置，也不读取 Relay 的密钥快照。
- `features/translation` 拥有请求构造、响应解析、60 秒截止与取消、固定中文错误映射；Provider 选路、鉴权、重试与密钥继续由 `scriptmgr-go/internal/relay` 拥有。
- 设置页新增翻译目标语言和模型；默认简体中文、模型留空，用户需填写 Relay 可用模型。旧设置缺失翻译字段时采用默认值。
- Launcher 的翻译、剪贴板捕获、截屏和脚本均通过 `actionRegistry.execute()` 执行；翻译和脚本文本输出复用 `ActionTextOutput` 展示、复制和写入 Inbox。翻译保存包含原文与译文。
- 翻译支持显式取消；关闭、原生隐藏或再次唤起时中止旧请求并隔离迟到结果。脚本和其他不能停止的动作不提供取消按钮。
- Windows 快捷键 / 中键入口现在会在 Launcher 聚焦前通过系统复制读取当前前台选区，并短暂记录来源窗口；结果面板提供用户显式触发的“替换原文选区”，原生侧恢复来源窗口、粘贴译文并恢复原有文本剪贴板。非 Windows 保留明确不支持错误；当前仍需打包态验证不同编辑器、权限和剪贴板格式边界，不能据此宣称 F2 已完成。
- 真实模型请求与 Windows 打包态仍待验收；本机 Relay 未运行时应显示连接指引。Relay / ScriptMgr 的 loopback-only 监听、来源白名单和配置快照脱敏已实现；剩余边界包括本机 `relay.json` 的兼容明文密钥、同机进程访问 loopback，以及 header 名称启发式的限制，见 ADR-0007。

### Gate F2

- 无 Provider、网络超时、鉴权失败、限流和空输入有可读反馈。
- 至少一个 Provider adapter 有 mock 测试；动作层不绑定具体供应商。
- 翻译结果能从 Launcher 回流到剪贴板和 Inbox。

## 6. Phase 3：Retrieve

### 首条切片（2026-10-17）

- Manager 新增受控 `Files` builtin 面板，作为本切片的文件入口；Launcher 文件搜索整合留待后续切片评估。用户显式选择一个目录后，首次索引由点击刷新建立；成功的文件操作会触发操作后的索引重扫，不做启动扫描或后台 watcher。
- Rust `file_search` owner 持久化 root / paused 配置，索引结果携带 generation；typed bridge 将 generation 传给预览、打开、定位、复制路径、重命名、移动、复制和回收站删除，防止操作过期结果。
- 最近打开记录写入现有 `notes.db` 的独立表，最多保留 100 条；仅记录从 Files 面板成功打开的路径，读取时仅返回当前配置目录中仍存在的项目。最近记录独立于内存索引，不计入索引数量。文本预览有 512 KiB 上限，图片预览有 4 MiB 上限并返回 data URL。
- 暂停会保留已有索引供查询，但阻止手动刷新；暂停期间执行成功的文件修改会清空索引并更新 generation，恢复后需再次刷新。复制和移动目标必须位于当前配置目录内；本切片 UI 的重命名、移动、复制和回收站操作仅支持普通文件。
- 当前实现是单目录 MVP；多目录、分页、实时 watcher 和全盘索引留后续版本。Windows 打包态回收站、权限、锁定文件和长路径仍需人工 smoke。

### 任务

- 搜索索引仅覆盖用户指定的单一目录；最近打开记录是独立数据，只展示当前目录内 Files 面板成功打开且仍存在的路径。索引可暂停、刷新和清除。
- 支持文件名、路径、扩展名、模糊搜索和最近访问排序。
- 搜索结果提供打开、定位、复制路径；普通文件支持重命名、移动、复制和回收站删除。移动和复制目标必须位于配置目录内。
- 文本和小图轻量预览；其他类型无法预览时回退到系统默认应用。
- 文件锁定、权限不足和目标冲突必须在 UI 中说明，不静默覆盖。

### Gate F3

- 指定目录内的样例文件可搜索、预览、打开和定位。
- 索引范围之外的文件不会被悄悄扫描，后台资源占用可观察。
- 删除默认进入 Windows 回收站；不支持回收站时禁止静默永久删除，并提供明确的失败提示。
- 自动化已覆盖 9 项 native file-search 测试和 Files 面板 / bridge 回归；Windows 打包态仍需按 checklist 验证回收站、权限、锁定文件和长路径。

## 7. Phase 4：Download

### 实施决策（2026-10-17）

- 下载器归 Tauri native `download.rs`；ScriptMgr 继续只负责脚本任务，不承接普通文件下载。
- 队列记录保存在 native 进程内，目标目录和冲突策略持久化；应用完全退出不承诺恢复未完成任务，`.part` 临时文件可在下次添加相同 URL 时尝试 Range 续传。
- 下载写入同目录随机 `.part` 文件，成功后再重命名到最终文件；默认冲突策略为自动改名，用户可选择报告冲突或覆盖；覆盖需要在提交下载前明确确认。
- 前端经 typed bridge 轮询状态；状态包括 queued、downloading、paused、completed、failed、cancelled，错误必须保留可重试信息。
- 详细边界见 [ADR-0005](../decisions/ADR-0005-download-owner-and-safety.md)。

### 任务

- URL 解析、下载队列和目标目录配置。
- 状态模型覆盖 queued、downloading、paused、completed、failed、cancelled。
- 支持暂停 / 继续、取消、失败重试、文件名冲突策略和完成后动作。
- 下载结果可打开、定位、复制路径或进入 Inbox。

### Gate F4

- 自动化已覆盖 URL 校验、入队、暂停和 Inbox 回流；Rust 聚焦测试已覆盖 URL、URL / Content-Disposition 文件名解码、命名、冲突候选、控制标志、成功写入 `.part` 以及取消时保留 `.part`（当前 11 项）。Reqwest 使用默认 Rustls crypto provider，避免下载 worker 在运行时因 provider 缺失 panic。覆盖确认、取消、失败重试仍由打包态 smoke 覆盖。
- 仍需在 Windows 打包产物中覆盖一个公开样例资源的成功、取消、重试、冲突和权限场景。
- 网络异常不会阻塞 Launcher 或 Manager 其他操作。
- 下载完成通知不会抢占用户正在使用的专注软件。

## 8. Phase 5：Voice

### 设计基线（2026-10-17）

Phase 5 先交付 Windows-first 的本地录音闭环，不把转写作为首个 slice 的完成条件。录音 native owner 为 `easyflowhub-app/src-tauri/src/voice.rs`，前端只通过 typed bridge 控制会话；停止后原子保存 `48 kHz / mono / 16-bit PCM WAV`，再以现有 Inbox 附件流程创建 `audio` 附件。录音中必须有可见状态，窗口隐藏不停止会话，应用完全退出不承诺续录；未完成的 `.part` 文件保留并标记中断。

细化设计、权限与隐私边界见 [ADR-0006](../decisions/ADR-0006-voice-recording-and-inbox.md)。首个实现完成后再单独决定是否接入转写 Provider / local model adapter；在用户确认上传前不发送音频。

### 任务

- Windows 麦克风权限、默认设备和设备占用提示的最小配置；设备选择作为后续扩展。
- 录音会话状态：recording、paused、stopped、saved、failed。
- 录音中显示可见状态和麦克风占用提示；不得在后台静默录音。
- 音频原件进入 Inbox，保留来源、时间、标题和 `audio/wav` 附件；失败时清理事务临时文件并保留未完成 `.part`。
- 为后续 Provider / local model adapter 预留关联字段；本 slice 不自动转写、不上传网络。
- 在 Gate F5 前确定默认格式、保存位置、清理入口、麦克风权限反馈和隐私提示。

### 当前实现（2026-10-19）

- 已完成 Windows 专用采集线程、默认输入设备、`cpal` 流控制和 `hound` WAV 写入；格式固定为 `48 kHz / mono / 16-bit PCM WAV`。
- 已完成 `.wav.part` 到 `.wav` 的停止提升、Inbox `audio` 回流、失败路径保留音频路径，以及 Voice 面板的暂停 / 继续 / 停止、状态轮询、打开录音和收集箱跳转。
- 转写切片（2026-10-19）已按 [ADR-0008](../decisions/ADR-0008-voice-transcription-and-relay.md) 交付：native `transcription.rs` 经 `TranscriptionTransport` trait 调用本机 Relay `POST /v1/audio/transcriptions`，25 MB / 180 秒边界、固定中文错误分类、`transcript` 附件与 convert-to-note 嵌入；前端共享 `TranscribeControl` 在 Voice / Inbox 面板提供发送前的 Provider 与隐私确认，设置页「转写」段保存模型 / 语言偏好。
- 自动化验证已覆盖前端 Voice 生命周期与 bridge、Voice / Inbox / Settings 转写确认流、Rust voice fake backend 与转写聚焦测试；仍需 Windows 打包态麦克风权限 / 设备占用 / 隐私设置和真实 WAV 播放 smoke。

### Gate F5

- F5 是 P2 阶段门槛，不阻塞 P0/P1 核心 RC；若 RC 包含 Voice，Windows 打包态 smoke 必须通过。未验收时 Phase 5 保持 `in_progress`。
- 录音开始、暂停、继续、停止和重开可重复完成。
- 关闭窗口或转写失败不会丢失已保存音频。
- fake `AudioCaptureBackend` 覆盖状态和失败路径；Windows 打包 smoke 覆盖默认设备、权限、隐藏窗口、WAV 回流和 `.part` 保留。转写 slice 另需真实 Provider 至少一次成功转写、重新打开 Manager 后 transcript 仍可读取，以及 Relay 未启动 / 模型未配置 / Provider 不支持转写接口时的可理解失败。

## 9. Phase 6：Glass Theme

### 任务

- 建立颜色、表面、边框、阴影、blur、opacity、radius、spacing、typography tokens。
- 迁移 Manager、Launcher、Quick Note、Settings 和捕获 / 结果浮层。
- 移除暖黄色和米色的页面级硬编码，保留用户内容的原始颜色。
- 为 hover、focus、selected、disabled、error、loading、dragging 定义状态 token。
- 在不支持 backdrop blur、关闭透明效果和 Windows 高对比度场景中验证 fallback。
- 对截图、录音和下载等高反馈操作保持稳定的状态层次，不让玻璃材质隐藏错误。

### Gate F6

- 主题在开发态和 Windows 打包产物中视觉一致，核心文字和控件可读。
- 低性能或透明效果关闭时没有重叠、闪烁或不可操作状态。
- 主题迁移不会改变笔记 Markdown 数据和附件路径。

## 10. 测试与交付矩阵

| Rust / Tauri | Windows 外部应用检测 / 启动、窗口、权限、下载或录音 native bridge | 命令注册、错误映射和取消路径可检查；Snow Shot MCP 初始化、截图工具调用、注册表 / D 盘发现、自定义路径优先级及安装页分支有测试 |
| Go | 文件索引、下载队列或 Provider sidecar（若复用） | 包级测试和失败场景测试 |
| Windows smoke | 中键、排除软件、打包窗口、托盘、权限、文件和麦克风 | 每个 Gate 至少一条人工 smoke |

## 11. 依赖与风险

- Windows 外部应用启动、低级鼠标 hook、全局快捷键和麦克风权限必须在真实打包产物中验证；Snow Shot 安装版与 portable 路径至少各验证一条发现路径。
- Snow Shot 没有作为 EasyFlowHub 的捆绑依赖；其安装、更新、许可证、MCP 开关和快捷键由用户自行管理。启动截图依赖随 Snow Shot 提供的官方 MCP bridge；协议和工具名应有兼容性检查，不能把 MCP 未启用解释为未安装。
- 任何外部翻译 / 转写 Provider 都可能受限流、网络和凭据影响，动作层必须能降级或重试。
- 全盘索引、OCR 和实时转写容易扩大资源占用，先以明确范围和可取消为边界。
- 玻璃效果可能造成性能和对比度问题；不透明 fallback 与可读性门槛优先于视觉完整度。
- 下载、录音和截图都产生本地文件，必须在设置与文档中说明默认位置和清理方式；Snow Shot 的截图保存位置由 Snow Shot 管理，EasyFlowHub 不应假设其路径或静默移动文件；录音发布前还要明确麦克风权限、文件格式和外部 Provider 发送策略。

## 12. 完成定义

- PRD 中的 P0 主路径在 Windows 打包产物可用，并有对应回归记录。
- P1 至少完成文件搜索和下载的稳定闭环；P2 作为 `v0.2.x` 后续能力，若发布则以录音保存和录音后转写为边界。
- 新能力均有明确 owner、输入 / 输出契约和失败反馈，不在页面中新增孤立实现。
- Snow Shot 外部动作在 MCP 已启用时能打开截图界面，在未安装环境中优雅降级到官方安装页，且不阻塞其他 Launcher 动作；自动截图结果回流 / OCR 另立技术设计后再进入版本范围。
- 主题 token 覆盖主要页面，暖黄色硬编码被迁移或明确标记为用户内容。
- roadmap、PRD、ADR、计划和相关 `MODULE.md` 已同步到同一版本边界。
