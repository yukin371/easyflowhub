# 工作台的「彻底删除」二次确认

> 状态：`completed` —— 对话框、Esc 分层、四条门禁断言都已落地；清空回收站与批量选择留给下一批

## 1. 为什么是确认，不是撤销

工作台里唯一的不可逆操作是 **彻底删除**：它 `DELETE` 掉那一行，不是移到回收站。上一批的门禁
就是单击它把 `gate-live-2` 删掉的——这恰好也是用户发现它的方式，只是代价不同。

撤销在这条链上不存在：没有日志表、没有软删除的第二层、也没有"最近删除"缓存，所以"先删再撤"
只能靠事后补一个快照，而那正是用户不会记得点的东西。**在没有撤销能力的地方，唯一的诚实做法是
先问一次。**

## 2. 为什么待确认是视图状态，不是 `Action`

`Action` 的语义是"用户决定了这件事"。一个已经弹出、还没回答的问题是**问题**，不是决定。
如果把它做成 `Action::AskPurge`，控制器就得知道怎么画一个对话框——那是把绘制塞回 `app`，而
这条分层（`hub-ui` 只画，`app` 只管副作用）是管理器能被无窗口测试的原因。

所以待确认挂在 `State::pending` 上，只有第二次「是」才产出 `Action::Purge`。控制器唯一需要知道
的是 Esc：它默认关窗，而对话框打开时它必须只取消对话框。这就是 `State::dismiss()` 存在的理由——
**返回值**（而不是副作用）让控制器能在"取消对话框"和"关闭工作台"之间做选择。

Esc 的检查在 `draw()` 之前，所以对话框那一帧根本没被画出来，`egui::Modal::should_close()` 不会
重复消费它。

## 3. 对话框本身

- `egui::Modal` + 自绘 `Frame`（`surface` 填充、`border_strong` 描边、10 px 圆角），背景按
  `Modal` 默认的黑色 alpha 100 压暗——点背景等于「取消」，永远不会是「是」。
- 按钮 `取消` / `彻底删除`（`danger` 填充 + `on_accent` 文字），两个都上报矩形
  （`confirm-ok` / `confirm-cancel`），门禁按上报的坐标点，不猜。
- Enter 也是「是」，但要求**当前没有输入框持有焦点**：搜索框里一个手滑的回车不该删掉一条笔记。
- 文案带标题（「{title}」会从数据库删除，回收站也找不回来），因为"我删的是哪条"是这类对话框
  唯一真正要回答的问题。

## 4. 门禁怎么判（四条）

`scripts/check-native-manager.py` 32 → **35**，连跑三次全 PASS：

1. `彻底删除 asks before it deletes anything` —— 点一次后日志有 `manager_confirm action=ask`、
   `confirm-ok` 矩形被上报，但库里那行**还在**（`rows=(1,)`）。
2. `取消 keeps the note and closes the dialog` —— `action=cancel`，行还在。
3. `Esc cancels the dialog and leaves the workbench open` —— `action=cancel reason=esc`，行还在，
   **工作台窗口还在**（这条是分层的证据：不修就是 Esc 把整个工作台关掉）。
4. `the second yes removes the row for good` —— `manager_purge ... permanent=true` +
   `action=ok` + `rows=(0,)`。

第 4 条换成"直接点彻底删除就没了"是不行的：那正是改动前的行为，会因为状态恰好残留而通过。

## 5. 门禁顺手揪出的三个真 bug

- **点回收站里的行不重绘**。选中发生在 `allocate_exact_size` 之后，而这一帧的高亮和
  「恢复/彻底删除」已经按旧选中状态画完了；没有新的一帧就什么都不变。原来它靠"下一个鼠标移动"
  偶然可见，门禁等不到就报红。修法是点击时 `request_repaint()`——这是产品缺陷，不是门禁幻觉。
- **写库后列表不重绘**。`reload()` 换掉了行，但这一帧已经画了一半，egui 不会自己再画一帧：
  恢复后的行还留在回收站位置，直到鼠标动一下。`refresh(ctx)` 在四个写动作后各请求一帧。
- **确认框重开不写命中行**。矩形只在"位置变了"时写日志，第二次在同一位置打开就什么都不写，
  门禁从某个点开始看日志永远看不到它。改成"这一帧没上报的名字就忘掉"，重新出现时必然再写一行。

顺带修了门禁自己的一个坑：`clear_spot` 在工作台被笔记窗口盖住时左右各挪 160 px，**在两点之间
来回震荡**六次也不会变干净。现在改为移动**挡路的窗口**（+900/+520），方向固定，六次不会互相
抵消。原因是那条笔记的窗口标题还没写上，`park_spawned_notes()` 按标题找不到它。

## 6. 没做

- **清空回收站**：一次删掉全部，同样需要确认，但还需要批量接口（`purge_all_trashed`）。
- **多选与批量恢复**：旧版前端有（`TrashPanel` 的 `selectedIds` + `恢复选中`）。
- 回收站保留期（30 天）的说明文案与自动清理：`deleted_at` 已经有了，清理任务还没有。
