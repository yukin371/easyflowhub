# 工作台的视觉骨架

> 状态：`completed` —— 侧栏、面板头、行与留白都已对齐旧版的层次；行为一条没改，命中名一条没动

## 1. 这一刀为什么排在第一个

`2026-11-28-manager-parity.md` 里量过差距，也给了 A/B/C 三条路线；A 的第一刀不是功能，是**像不像
同一个产品**。理由很实际：后面四刀（回收站批量、待办可勾选、笔记视图、设置分节）都要往这套壳里
填内容，如果壳本身没有层次，每填一块都要重排一次。

所以这一批只改外观：宽度、字号、留白、圆角、分区。**没有任何一个新行为**，`Action` 没加一个变体，
门禁的命中名（`tab:notes` / `new-note` / `todo-card` / `row:<id>` / `pin:<id>` …）一个没改——它们
是脚本唯一认识的东西，改外观不该让脚本跟着改。

## 3. 三个值得写下来的决定

**图标块里放汉字，不放 emoji。** `🗑`、`⚙` 依赖系统 emoji 字体，在精简安装的 Windows 上会变成
tofu；而 `theme::install_*` 一定装了一个覆盖「笔/办/删/设」的 CJK 字体。导航是唯一不能出现豆腐块
的地方，所以选必然存在的字形。代价是图标语义弱一点，换来的是「永远不会坏」。

**子模块而不是继续长。** `manager.rs` 早过了 800 行的边上，这一批把侧栏（`nav.rs`）、面板头
（`head.rs`）、行模型（`row.rs`）和测试（`tests.rs`）各拆一份。拆的依据是"谁和谁没有共享状态"，
不是为了行数好看：`nav.rs` 只读 `State.tab`，`head.rs` 只写 `state.hits`，`row.rs` 是纯数据。

**状态条不进面板头。** 旧版没有状态条，原生版有（「已移到回收站」是必要的反馈）。把它放在
内容区底部而不是标题下，是因为它出现的时机恰好是列表刚变的时候——放在标题下会让整张列表跳一
下，正好在用户盯着的时刻。

## 4. 顺手修的一个真问题

列表行的预览与标题**完全相同**：笔记的常见写法是「标题\n正文」，而 `preview_of` 只跳过空行和
`#` 标题，于是每一行都读成「周报 / 周报」。截图里一眼就能看到，修法是 `preview_of(content, title)`
跳过与标题相同的那一行；只剩标题的笔记则预览为空，行按单行居中。`hub-ui` 里钉了一条测试
（`a_row_preview_never_repeats_its_own_title`）。
