# 回收站收尾：子页签、多选、批量恢复、清空

> 状态：`completed` —— 三个子页签、逐行勾选、恢复选中、清空回收站（带确认）、30 天到期清理都已落地；
> 另外两个子页签给的是说明而不是列表

## 1. 子页签：只有「笔记」有列表，另外两个给答案

旧版面板的回收站装三类东西（笔记 / 收集项 / 脚本），因为 Tauri 管理器三类都管。原生工作台只拥有
笔记，所以另外两个 chip 点进去是一句话："收集箱条目的回收站在 Tauri 版管理器里；原生工作台只处理
笔记。"

三种写法里选了这一种：

- **灰掉不可点**：最省事，但它是一个死控件，而且"点不动"和"坏了"在用户眼里是同一件事；
- **空列表 + "收集箱是空的"**：这是对一份这个窗口根本看不见的数据下结论，比不说更糟；
- **点进去给一句解释**：点击有回应，回应是真的，而且它顺便回答了"我删掉的收集项去哪了"。

选择器是 `State.trash_view`（`TrashView::{Notes, Inbox, Scripts}`），切换会走
`Action::SetTrashView` —— 和待办筛选同一个理由：它是视图状态，但日志需要能回答"列表怎么是空的"。

## 2. 一行两个动词，一个命中区按 x 分流

回收站的行要能被**挑中**（批量恢复），也要能被**选中**（在它下面出现 恢复 / 彻底删除）。两块重叠的
点击区在 egui 里只有最后注册的那个拿到点击，所以没有做两个控件：行仍然是一个 `Response`，按点击位置的
x 分流——左边 30 px 是勾选列，其余是选中。

**勾选不选中**，这是有意的：选中会展开一条按钮带，把下面每一行推下去，于是批量勾第二行时点击会落在
"移位后"的那一行上。待办页的方框/文字也是同一个理由。

勾选列的点击区是整个 30 px 列（画出来的方块是 14 px）：14 px 是装饰的尺寸，不是控件的尺寸。门禁读到的
`check:<id>` 矩形是 `30×48` 点（截图上 45×72 物理像素），点在正中。

## 3. 批量条：出现与消失都由选择决定

「已选 N 条 · 取消选择 · 恢复选中」是搜索框与列表之间的一条，**只在有勾选时存在**。
`恢复选中 (0)` 是一个只能失败的按钮，所以不做常驻。

`Action::RestoreSelected(Vec<String>)` 带着 id 列表走：控制器从不读视图状态，而日志因此能写出
`count=2 ids=gate-trash-2,gate-trash-3`。集合是 `BTreeSet` 而不是 `HashSet`——同样的两次勾选，
日志行每次一样，diff 才读得下去。

每帧还会拿当前回收站的 id 集合剪一次 `checked`：一条被别处恢复（或到期清理掉）的行不该继续占着
"已选 N 条"里的那个 1。

## 4. 清空回收站：只在有东西、且只在「笔记」页出现

- 空回收站不显示这个按钮——常驻的破坏性按钮只会被误按，而且它只能回答"清空 0 条"；
- 切到「收集箱 / 脚本」时也不显示：它清的是**这份列表**，站在一个"笔记在别处"的页面上放一个
  删除按钮，是把两个意思混在一起；
- 点击进 `Pending::EmptyTrash { count }`（对话框里要说出条数，"清空回收站？"没有数字是没法回答的），
  只有对话框的"是"才产出 `Action::EmptyTrash`。**问题不是决定**，和 `Pending::Purge` 同一条规则。

## 5. "保留 30 天"从一句话变成一个行为

面板从有摘要那天起就写着"删除的笔记保留 30 天"，而在此之前**没有任何代码在做这件事**——回收站只
会长大。这一刀补上：

- `Store::purge_expired_trash(now, days)` 删 `deleted_at < cutoff` 的行，cutoff 由 `clock::unix_ms`
  → `iso_from_unix` 算出来，**文本比较**成立的前提是两边都是同一宽度、同一时区的 UTC 串（两个构建
  都写这一种）；
- 读取不到的 `now` 是 no-op 而不是按 1970 处理：这是在一个页签点击里发生的删除，猜错就是数据丢失；
- 触发点是**打开回收站**（`Action::SetTab(Trash)` 与 `set_tab` 两条入口都会调），也就是用户读到
  这句话的时刻；清理了就在状态行说明条数，日志写 `manager_trash_expire days=30 purged=N`；
- `TRASH_RETENTION_DAYS` 是唯一一份数字，面板的两处文案（头部摘要、空状态）都从它来。

## 6. 存储层新增三个方法

| 方法 | 语义 |
|---|---|
| `restore_notes(&[String])` | 一个事务里恢复多条；`deleted_at IS NOT NULL` 保证返回值是"真的从回收站出来了"，而不是请求的条数 |
| `purge_trashed()` | `DELETE ... WHERE deleted_at IS NOT NULL`，清空就是"这个集合" |
| `purge_expired_trash(now, days)` | 到期清理，见上 |

三个都有单测：批量恢复的计数语义（活着的笔记不算）、清空不碰活行、清理只删过期的、`now` 读不懂时
什么都不删。
