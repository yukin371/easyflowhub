| 维度 | 为什么自动化测不了 |

## 5. 一轮怎么跑

### 5.1 启动

```powershell
cd E:\Github\AllScripts\easyflowhub
New-Item -ItemType Directory -Force -Path .\docs\releases\native-c2 | Out-Null

.\native\target\release\easyflowhub-native.exe --editor --demo `
  --log .\docs\releases\native-c2\run-1-microsoft-pinyin.log
```

- `--editor`：面板里放 RichEdit 文本岛（否则是动作网格）
- `--demo`：启动后**自动打开面板并保持**，不用先按热键
- `--log`：把 `editor_created` / `set_ppp` / `editor_esc` 等事件写进文件，出异常时用来对时间戳

面板逻辑尺寸 440×860，编辑器字号 `11 pt × ppp`，字体 `Microsoft YaHei UI`。

### 5.2 三件事先做掉

1. **清空预填文本**：编辑器创建时会预填 120 字《千字文》（`天地玄黄宇宙洪荒…`），光标在末尾。`Ctrl+A` → `Delete` 清空后再开始，否则你会以为那是异常。
2. **确认焦点在编辑器里**：点击一下编辑区中部，光标应出现。S2 修过"不聚焦则超一屏不跟随"，这里顺带回归。
3. **确认能打字**：输入 `测试` 两个字，正常上屏再进节拍表。

### 5.3 热键与 ESC 的行为（容易误判成崩溃）

| 操作 | 行为 |
|---|---|
| `Ctrl+Shift+Space` | 面板开关（打开时再按会隐藏 —— 这是设计行为） |
| `Esc`（焦点在编辑器内） | 面板隐藏（park），**程序不退出** |
| `--demo` | 只在启动时自动打开**一次**；被关掉后要用热键重新打开 |

热键注册失败时程序会打印错误并 `exit(3)`。如果被输入法或截图工具抢占，用 `%APPDATA%\com.yukin.easyflowhub\native-spike.json` 覆盖热键（settings 带 `#[serde(default)]`，只写要改的字段）：

```json
{ "hotkey": "Ctrl+Alt+F9" }
```

#### 5.3.1 Esc 曾经要按好几次 —— 已修，但有一半属于正常现象

首轮实测（`docs/releases/native-c2/run-1-microsoft-pinyin.log`）报告"按了 3 次才关掉"。日志里只有 **1 条** `editor_esc`，说明前两次按键根本没走到回调。分两层查完：

| 层 | 结论 | 证据 |
|---|---|---|
| 控件投递 | **没问题**：3 次 `WM_KEYDOWN` → 3 次回调，`LRESULT=0` | `cargo run -p hub-editor --example esc_probe` |
| 帧调度 | **有缺陷**：标志置位后没有任何帧被安排，`update` 不来读它 | 见下 |

缺陷在 `app` 侧：Esc 被子类过程吞掉，winit 看不到它，因此不会唤醒事件循环；而交互模式下 `settle` 之后不再请求重绘，编辑区是 RichEdit 自己画的，也不需要 egui 出帧。于是**标志只是躺在那里，等一个无关的鼠标消息把它读走** —— 这正是"有时按一次、有时按三次"的来源，取决于你按的那一刻有没有别的事件。

修复：回调里置位的同时 `ctx.request_repaint()`，从按键发生的地方请求一帧。

用同一份 Esc 自动对比（探针向 RichEdit 子窗口 `PostMessage` 一次 `WM_KEYDOWN`，500 ms 后看窗口矩形）：

| 二进制 | 日志 | 窗口位置 |
|---|---|---|
| 修复前 | **0 条** `editor_esc` | `+619+524` → 未移动 |
| 修复后 | `editor_esc panel parked, presses=1` | `+619+524` → `-20000-20000` |

**仍然是正常现象的一半**：候选窗打开或处于组合态时，第一次 Esc 被输入法用于关候选窗 / 取消组合，**不会**送到编辑器。这不是缺陷，是 Windows 输入法的标准行为。区分办法看日志：

- 面板在第一次按下的瞬间就隐藏 → 正常，`presses=1`
- 要先关候选窗再按一次 → 前面那次没有 `editor_esc` 记录，属于输入法吃了键

**焦点残留已修（2026-11-25 15:20，run-1 作废之后）**。此前 park 只是把窗口移到屏幕外，窗口仍然可见、仍是前台，**焦点也仍然留在编辑器里**，所以面板隐藏后继续打字，字符会静默写进那个看不见的编辑器（`esc_probe` 曾实测 `focus_is_editor=true` / `typed='a' chars=1`）。现在 `park` 会同时 `SetFocus(null)`：

| 探针（`scripts/esc_poke.rs`，按 PID 找窗口） | 修复前 | 修复后 |
|---|---|---|
| `focus_is_editor_after` | `true` | **`false`**（`focus_after=0`） |
| `result` | （无判定） | **`PASS`** |
| 窗口位置 | `-20000-20000` | `-20000-20000`（未变） |

日志侧同步可见：`editor_esc panel parked, presses=1 focus_released=6228652 focus_after=0`。

**但只修了一半，half 在哪要说清**：前台（foreground）仍在面板上，`esc_poke` 报 `foreground_is_target=true`。所以按 Esc 后击键**不再**进编辑器（这是会丢数据的那一半，已解决），但焦点没有自动回到你原先那个窗口，需要点一下或 `Alt+Tab`。把前台还回去会让下一次 `SetForegroundWindow` 走前台锁协商，从而改变 bench 的测量条件——那属于 Phase 1 的必答题，不在这批里顺手改（S1 的 p95 全程在本进程已前台的乐观条件下测得，见 [S1 文档](../completed/2026-11-25-native-shell-spike.md) 的"测量条件"）。

**因此本轮纪律仍然是：按 Esc 之后先看一眼目标窗口**。只是原因从"会静默写入"变成"焦点不会自动回来"，代价从丢字降为多按一下。

bench 侧也加了牙齿：`--bench` 每次 park 后读一次焦点，`---FOCUS---` 段输出 `parks` 与 `left_focus_in_panel`，**非 0 直接 exit 2**，不再靠人工看一眼。本次 30 轮实测 `{"parks":30,"left_focus_in_panel":0}`，`shown p95=48.8 ms`（与 S1 的 48.9 持平，p99 48.8，预算 60/100 均 PASS）。

### 5.4 30 分钟节拍表（每种输入法一轮）

"连续"的可操作定义：**同一进程内累积 ≥ 30 分钟，中途可短暂停顿，但不要重启程序**（IME 状态在进程内持续；重启则该轮作废重计）。这条是本节对判据的解释，不是放宽 —— 若你认为必须一次坐满，按一次坐满做。

| 段 | 时长 | 做什么 | 想抓什么 |
|---|---|---|---|
| 1 | 0–5 min | 打 20 条短句，句末分别用 `，。？！` 和 `,.?!`（`Shift` 切中英标点） | 标点是否按模式出、有没有出成全角/半角错配 |
| 2 | 5–10 min | 长句 + 多候选词：用 `+`/`-` 或 `,`/`.` 翻页（各输入法不同），`空格` 上屏，数字键选词 | 候选窗是否贴光标、翻页键是否被吞、候选序号与上屏是否一致 |
| 3 | 10–15 min | 中英混输：如「把 README 里的 p95 改成 4.95 ms，再跑一次」 | `Shift` 切中英是否卡住、英文单词后首个中文是否丢字 |
| 4 | 15–20 min | 编辑操作：逐字退格（含删到组合态）、`Ctrl+Backspace` 删词、`Home`/`End`/方向键移动后继续输入、选中一段替换、`Ctrl+A` 清空重打 | 组合态下退格是否错乱、移动光标后首个字是否丢失、选区替换是否残留 |
| 5 | 20–25 min | 连打 `Enter` 30 行让光标超出一屏，在底部继续输入；再滚回顶部输入 | 光标是否自动跟随（S2 修过的那条）、滚动后候选窗是否跑到屏外 |
| 6 | 25–30 min | `Esc` 隐藏 → 热键重开 → 继续输入；然后不间断快速打 200 字 | 重开后 IME 是否仍可用（重新创建/复用路径）、高频输入是否丢字或串行 |

**每段结束顺手记一行**（§7.2），不用写整段过程，只写"ok"或异常编号。

## 6. 全程盯的 6 个观察点

每个观察点给一个"正常长什么样"，否则"异常"会变成主观判断：

| # | 观察点 | 正常 | 异常形态 |
|---|---|---|---|
| O1 | 候选窗位置 | 紧贴光标**下方**（贴到屏底时翻到上方），不遮住正在输入的那一行 | 跑到屏幕角落、停在旧位置不跟、出现在面板外的桌面某处、被面板裁掉一半 |
| O2 | 组合串 | 拼音串在光标处带下划线显示，随按键**逐字**更新 | 串不显示（盲打）、显示位置偏移、更新滞后一整词、字母直接上屏未经组合 |
| O3 | 上屏一致性 | 选中的候选 = 屏幕上出现的字 | 丢字、多字、顺序颠倒、候选序号与上屏不一致 |
| O4 | 标点与全半角 | 中文模式出 `，。`，英文模式出 `,.`；`Shift+Space` 切全半角后按设置生效 | 中英标点混出、全半角切换无效、引号/括号配对错 |
| O5 | 光标跟随 | 输入到可见区底部时视图自动滚动，光标始终可见 | 光标被顶出可视区、滚动滞后一行、滚到一半停住 |
| O6 | 视觉稳定 | 文本岛背景与面板背景同色（`panel_strong`），无接缝、无闪烁 | 打字时闪一帧白/黑、子窗口与面板错位、残影 |

## 9. C2 算不算过 —— 决策规则

C2 要回答的是**"编辑器交给系统"这个栈选择**对不对，不是"这个控件零缺陷"。所以：

| 情况 | 结论 |
|---|---|
| 无 S/A 级 | **C2 通过**。B/C 级进 Phase 1 backlog，按普通缺陷修 |
| 只有一种输入法出现 S/A 级 | **C2 通过**（栈没问题）。记为该输入法的具体缺陷，Phase 1 内修；若修不掉，评估对该输入法的静默降级 |
| 三种输入法都出现**同类** S/A 级 | **C2 不通过**。这是编辑器实现问题，不是输入法问题 → 触发 ADR-0009 的编辑器可替换边界，Phase 1 内换实现（退路：WebView 编辑区），并在 G1 重新评审 |
| 有一种输入法装不上/未测 | **C2 未完成**，不能记通过。写明缺哪一种、原因、补测计划 |

判定"同类"要看观察点是否一致：三种输入法都在 O3（上屏不一致）出问题 → 同一个根因；一种是 O1、另一种是 O5 → 两个独立缺陷，不算系统性。
