# 原生工作台与旧版管理器的差距

> 状态：`active` —— 差距已逐项量过，切片顺序待定；本文件是"哪一条算对齐"的依据，不是进度日志

## 1. 为什么会有这个差距

接管态下 `Ctrl+Alt+M` 打开的是 egui 工作台（`native/app/src/manager.rs`），而它最初只被要求
"能看见笔记、能计数、能关窗"。旧的 React 管理器（`easyflowhub-app/src/components/manager/`）
在同一时期一直在长功能——它是一整个模块化工作台，有 224 px 侧栏、图标块、子页签、视图切换、
批量操作。于是同一台机器上，"有没有接管"决定了用户看到的是哪一个管理器。

这不是"还原旧版"的问题：接管态是产品方向，所以真问题是**原生工作台要承担其中哪些能力**。

## 2. 现状对照

| 区域 | 旧版（React） | 原生（egui） | 差在哪 |
|---|---|---|---|
| 侧栏 | 224 px，图标块 + 名称 + 英文副标题，Settings 钉在底部 | 132 px 纯文字四个页签 | 只剩"能点"，没有层次与图标 |
| 面板头 | kicker + 衬线大标题 + 一句摘要 + 右侧操作区 | 一行「工作台」+ 状态 + 两个按钮 | 没有标题/摘要，操作挤在同一行 |
| 笔记 | 笔记/收集箱双子页签；列表/网格/时间线三视图；标签筛选；行内改标题；Markdown 预览 | 单列表 + 搜索 | 视图与筛选全缺，标题只能改内容 |
| 待办 | 未完成/全部筛选、按笔记分组、就地勾选与改文字、跳转到笔记 | 筛选 + 分组 + 就地勾选 + 跳转 | 只剩行内改文字与新增待办 |
| 回收站 | 笔记/收集项/脚本三子页签、多选批量恢复、清空回收站（带确认）、30 天保留说明 | 三子页签**各有列表**（笔记 / 收集项 / 脚本）；多选 + 批量恢复；逐类清空（带确认）；30 天到期三类一起清理；收集箱的"彻底删除"连附件字节一起删 | 脚本回收站的**写入**（"删进回收站"）仍在服务里，原生只读列表 + 恢复 + 真删 + 清空；收集箱面板本身还没进原生；按删除日期分组没做 |
| 设置 | 分节（通用/启动/快捷键/关于…） | 只有快捷键表 | 启动项、外观、关于都没有入口 |
| 其他模块 | 脚本、文件、下载、MCP、扩展、语音、美化… | 无 | 这些是 Tauri 侧能力，原生壳没有对等物 |

## 3. 一个必须先回答的问题

上表最后一行不是"待补齐"，而是**待决定**：脚本 / 文件 / 下载 / MCP / 扩展这些面板依赖的是
Tauri 侧的服务与插件生态，原生壳里没有对等实现。三条路：

- **A. 只对齐四个核心区**（笔记 / 待办 / 回收站 / 设置），其余模块留给 Tauri 版管理器；
  接管态下侧栏不列出它们。
- **B. 保留入口但转发**：点击时打开 Tauri 版管理器（`create_manager_window` 的非接管路径），
  两个管理器并存。代价是两套 UI 同时存在。
- **C. 全部原生重做**：等于把整个模块系统搬一遍，超出 v1 的范围。

本文的推荐是 **A**：接管态的承诺是"笔记类工作流在原生里闭环"，脚本与扩展不是那条闭环的一部分。

## 5. 记账

- 第 1 刀只改外观时，门禁的命中矩形会全部位移——**已验证**：骨架落地后 35/35 仍全过，
  `check-native-manager.py` 一行未改。矩形由产品上报，脚本不需要知道布局。
- 旧版的三视图与标签筛选依赖前端 `todoParser` / `note` 类型；原生侧对应的模型在
  `hub_core` 里已有（`todo::lines`、`note_text::display_title`），不要再抄一份。
- 侧栏图标块用汉字（笔/办/删/设）而不是 emoji：换掉 `🗑`/`⚙` 是因为精简安装的 Windows 上
  它们会变豆腐块，而 `theme::install_*` 一定装了覆盖这四个字的 CJK 字体。
- 门禁读的是"上报过的矩形"，而矩形**只在出现或移动时**才写一行。所以新加的一刀如果把工作台
  留在同一个页签上，后面那句"再点一次这个页签、等一个新的矩形"就会一直等不到——第 3 刀就撞上了
  （卡片按钮的断言）。这不是产品缺陷：同一控件不动，本来就不该重复上报。门禁要的是"换出去再回来"。
- 完形符号（`✓`）不要当画法：它落在哪个字体、笔画多宽都不受控。14 px 的方框里画两条线段，
  在任何 DPI 下都是同一个形状，这也是待办卡片的圆点与面板的方框最终都改成手绘的原因。
- **文案可以先于行为存在，而那是要还的债**："删除的笔记保留 30 天"在回收站有摘要的那天就写上了，
  但直到第 4 刀才有代码删过东西。数字抽成 `TRASH_RETENTION_DAYS` 之后，文案与清理不可能再各说一套。
- **一行两个动词时，让勾选不选中**：选中会展开一条按钮带并把下面的行推下去，批量勾第二行就会点偏。
  同一理由也适用于待办页的方框/文字。点击区按 x 分流（一个 `Response`），而不是叠两个控件——
  egui 只把点击给最后注册的那个。
- **"不再出现"也要有证据**：断言某个控件消失时，先证明这一帧画过（换页签再回来，看新的 chip 矩形），
  否则"它没再上报"和"窗口卡住了"是同一份日志。
- **"彻底删除"在三种东西上是三个动词**：删笔记是删一行，删收集项还要删 `assets/` 里的字节，
  删脚本是删一个目录。确认框因此必须说出"这一行带走什么"（"--和它的附件会被删除"），否则同一个
  按钮在三个子页签上承诺的是三件不同的事。
- **读另一个进程的目录，只读**：脚本回收站的形状由 `scriptmgr-go` 定义，原生侧复刻 `entry.json`
  的字段但**不重做"删进回收站"**——那一步要判 roots 合法性、要有 rollback，第二份实现只会让两个
  进程对"什么算合法删除"各有一套意见。要读别人的数据，就把契约写在注释里并接受它的时间戳格式
  （本地 9 位小数 + `+00:00` vs `Z`，所以只比前 19 个字符）。
- **可行动的错误不要报成磁盘故障**：`StoreError::Refused`（目标已存在、id 会逃出目录）与 `Io` 分开，
  因为"这会覆盖你的文件"用户能处理，"磁盘坏了"不能。
- 本文件不记录单次改动；每刀完成后把"做了什么、证据、没做什么"写进 `completed/` 并回到这里
  划掉对应行。
