## 1. 产品定义

EasyFlowHub v0.2.0 是 Windows-first 的个人效率 Hub。它把用户在学习和工作中反复发生的四类动作放到同一条低打扰链路中：

1. **捕获（Capture）**：把屏幕、文字、文件、链接、语音和想法快速收进 Inbox；截图优先通过已安装的 Snow Shot 完成。
2. **理解（Understand）**：对选中文本、剪贴板和截图进行翻译、OCR 或转写。
3. **检索与整理（Retrieve）**：找到文件、笔记、录音和下载资源，并继续处理。
4. **执行（Act）**：通过 Launcher 调用脚本、文件、应用和后续小工具，把结果写回当前工作上下文。

v0.2.0 的目标是验证“一个入口减少多次切换”是否真的能提高个人用户效率。它不是一次完成的插件平台、云端知识库或完整音频工作站。

## 2. 用户与核心问题

### 2.1 首要用户

- **个人效率用户**：需要在浏览、阅读、写作、学习和日常办公中快速收集、查找、处理信息。
- **高级集成用户**：开发者和 AI 工作流用户，可以继续使用脚本、relay、MCP 等能力，但不作为普通用户的首屏主叙事。

### 2.2 主要问题

- 截图、翻译、记录和文件处理分散在多个应用，导致上下文丢失。
- 临时笔记保存后难以找到，图片、链接和文件附件与文字脱节。
- 文件搜索和下载是高频动作，却没有统一的结果回流入口。
- 录音和语音转文字通常是独立工具，无法自然进入笔记整理流程。
- 当前界面偏暖黄色笔记风格，无法表达“桌面效率 Hub”的工作空间属性。

### 2.3 核心场景

| 场景 | 用户动作 | 期望结果 |
|---|---|---|
| 阅读资料 | 鼠标中键唤起 Launcher，翻译选中文本 | 翻译结果可复制或直接写入 Inbox |
| 记录灵感 | 快捷入口打开快速捕获，输入文字或粘贴截图 | 内容自动保存为 Inbox 项，稍后可整理 |
| 处理截图 | 截取区域并标注 | 图片复制到剪贴板，同时可插入当前笔记 |
| 找资料 | 在 Manager 的 Files 面板输入文件名或路径片段 | 看到当前目录内的最近和匹配文件，可打开、定位或复制路径 |
| 下载资源 | 粘贴 URL | 看到队列和进度，完成后打开、定位或加入笔记 |
| 会议/学习 | 快速开始录音，结束后转写 | 音频原件和文本一起归档到 Inbox |

## 3. 体验原则

1. **先入口，后管理**：日常动作从 Launcher 或鼠标中键开始；Manager 用于整理、配置、审计和恢复。
2. **先捕获，后分类**：默认进入 Inbox，不要求用户在最忙的时刻先决定标签、文件夹或笔记类型。
3. **上下文优先**：动作应尽量读取剪贴板、选中文本、当前文件、当前窗口或最近截图。
4. **结果可回流**：动作结果可以写入剪贴板、文件、笔记、通知或下一个动作。
5. **渐进增强**：本地能力优先，外部 Provider 和 AI 能力通过可替换适配层接入。
6. **低打扰**：后台不抢焦点；用户通过快捷键或鼠标中键显式唤起 Launcher 时，应立即激活窗口并接收键盘输入。默认不置顶，遵循排除软件配置，不劫持已有快捷键；失败时给出可理解的恢复路径。

### 3.1 Launcher 交互约定

- 软件 / 工具和脚本 / 动作统一采用方块网格卡片，分组之间用细分割线区分；短名称常驻，详细说明通过悬停提示提供。
- 顶部只保留图标筛选、搜索、置顶、关闭及拖动区域；控件应具备可访问名称、悬停提示和快捷键说明。
- 搜索默认折叠，聚焦时直接输入自动展开；中文输入法组合输入不能丢字，鼠标可点击搜索图标展开。
- 每次唤起重置搜索并重新聚焦；`Esc`、关闭按钮、透明边缘点击或重复触发入口都可收起。拖动标题栏和短暂失焦不能误触关闭。
- 默认非置顶，用户主动选择后在当前进程中保持，重启恢复默认。`Alt+F4` 隐藏窗口，后续可再次唤起。
- Launcher 与快速笔记以鼠标为中心唤起，使用目标显示器的缩放比例，靠近屏幕边缘时限制在可用工作区。

### 3.2 外部工具协作边界

截图属于 Hub 的高频入口，但不在 v0.2.0 中重复实现截图渲染和标注能力。EasyFlowHub 通过一个内置外部动作调用 [Snow Shot](https://snowshot.top)，由 Snow Shot 负责全屏、窗口、区域选择和标注；EasyFlowHub 负责入口、安装状态、失败反馈以及后续的 Inbox / 文件回流。

- 动作标识固定为 `external.snow-shot.capture`，来源为 `external`，可出现在 Launcher 的搜索、最近和收藏中。
- 已安装且 Snow Shot 的 MCP integration 已开启时，通过随应用安装的 `snow-shot-mcp` bridge 启动 Snow Shot 并调用 `snow_shot_screenshot_begin` 进入可见截图界面；不模拟用户快捷键，也不依赖未经确认的命令行截图参数。
- Snow Shot 的 MCP integration 默认关闭，用户需在 Snow Shot「设置 → 系统」中显式开启。未开启或 MCP 不可用时，Launcher 显示开启方式和错误原因；不能误报未安装或跳转下载页。
- 未检测到可用程序时打开官方 Windows 安装页：<https://snowshot.top/download.html?os=windows>，并在 Launcher 中说明原因。
- 支持设置中配置 Snow Shot 可执行文件路径。检测顺序为“用户自定义路径 -> Windows 已安装应用注册信息（包括 D 盘等非系统盘）-> 常见安装目录 -> PATH”；不得静默启动不匹配的文件。MCP bridge 必须与被发现的主程序安装目录相邻。
- 不捆绑 Snow Shot 二进制、不复制其代码；安装、更新、许可证、MCP 开关、截图保存目录和 Snow Shot 自身快捷键由用户在 Snow Shot 中管理。自动截图结果回流、OCR 和翻译联动另行设计，不属于此动作的完成条件。

## 4. 信息架构与入口

### 4.1 Hub

Hub 是共享的产品概念，负责统一动作目录、Inbox、附件、执行反馈和最近记录。它不要求在 v0.2.0 中新增独立页面。

### 4.2 Launcher

Launcher 是高频动作入口，提供搜索、最近使用、收藏、参数输入和执行反馈。v0.2.0 应继续复用现有 action registry，并逐步把新能力注册为动作。

支持的入口顺序：

1. 鼠标中键点击（默认推荐的 Quicker-like 入口）。
2. 可重录的全局键盘快捷键。
3. 托盘菜单和 Manager 内的显式按钮。
4. 选中文本、复制文件或粘贴 URL 后的上下文动作。

全局入口必须支持：

- 按触发方式启用键盘、鼠标中键或两者并用。
- 指定排除软件，以进程名或可识别窗口进程为准；排除时不打开 Launcher、不改变当前软件输入状态。
- 录入时提示与已有系统快捷键或已配置动作的冲突。
- 注册失败时保留普通入口，并在设置中显示可修复原因。
- 触发期间不改变用户正在编辑的软件内容，除非动作明确要求写回。

### 4.3 Manager

Manager 负责 Inbox 整理、笔记和附件管理、下载队列、文件索引范围、录音转写记录、Provider 配置和主题设置。它是工作台，不是所有功能的必经入口。

## 5. v0.2.0 功能范围

优先级约定：`P0` 是版本必须形成稳定主路径的能力，`P1` 是完成检索和资源处理闭环的能力，`P2` 是在基础数据模型稳定后加入的语音能力。

### 5.1 P0：捕获与理解

| 能力 | v0.2.0 最小范围 | 验收口径 |
|---|---|---|
| 截屏（Snow Shot 外部动作） | Launcher / 中键唤起后通过 Snow Shot 官方 MCP bridge 启动应用并进入截图界面；已安装但 MCP 未开启时给出设置指引；未安装时打开官方安装页；保留 Snow Shot 的全屏、窗口、区域和标注能力 | 在 Windows 打包产物中点击动作可进入可见截图界面；覆盖 D 盘注册安装、自定义路径、MCP 开关状态、bridge 缺失、未安装和启动失败反馈；不要求 EasyFlowHub 自己实现截图编辑 |
| 快速笔记 Inbox | Launcher 一键收集剪贴板内容（执行时优先读取图片，回退文本）；Manager 可捕获文本、链接、剪贴板图片和文件；记录捕获时间、入口来源与捕获上下文；支持归档和整理为笔记 | 捕获后不选择分类也能保存；Snow Shot 复制截图后可直接从 Launcher 写入 Inbox；在 Notes 面板的“收集箱”视图中按时间查看、打开附件、归档或转换成笔记 |
| 翻译 | 选中文本、剪贴板文本；自动识别源语言；目标语言可配置；结果复制或写入 Inbox | 选中一段文本后可从入口得到结果；无 Provider、超时和限流时有明确反馈 |
| Launcher 上下文 | 输入支持剪贴板、选中文本、当前文件、截图和显式参数；输出支持剪贴板、笔记、文件、通知 | 至少两种 P0 动作能复用同一输入 / 输出契约，不在页面内复制特殊逻辑 |

截图 OCR 只在接口和数据模型中预留，本版本不以高质量 OCR 或 Snow Shot 结果自动回流作为发布硬门槛；后续仅在确认存在可复用的本地或 Provider OCR 能力后再接入。
Snow Shot 截图由用户在 Snow Shot 中复制后，可在 Launcher 执行“收集剪贴板内容”动作直接写入收集箱（动作会优先读取剪贴板图片）；也可以在 Manager 中粘贴。EasyFlowHub 不假定 Snow Shot 的保存路径，也不要求自动截图回流。

### 5.2 P1：检索与资源管理

| 能力 | v0.2.0 最小范围 | 验收口径 |
|---|---|---|
| 文件搜索 | 当前配置目录内的文件名、路径、扩展名和模糊匹配；最近记录独立于索引 | 输入关键词后能在可接受时间内返回结果，并可打开、定位到资源管理器或复制路径 |
| 文件基础管理 | 普通文件的复制、移动、重命名、删除；复制和移动目标必须位于当前配置目录内；删除默认进入 Windows 回收站 | 文件操作不会静默覆盖；权限、锁定和冲突有可理解错误；不支持回收站时禁止静默永久删除 |
| 文件预览 | 文本和小图轻量预览；其他类型打开系统默认应用；不在本版本做完整编辑器 | 搜索结果能快速确认支持类型的内容，无法预览时仍可打开原应用 |
| 资源下载 | URL 下载队列；进度、暂停、继续、取消、重试；目录和冲突策略可配置 | 下载过程中可看到状态；完成后可打开、定位、复制路径或加入 Inbox |

最近记录最多保留 100 条，仅记录从 Files 面板成功打开的路径；显示时只返回当前配置目录中仍存在的记录，不计入内存索引数量。当前文件入口是 Manager 的 Files 面板；Launcher 文件搜索整合留待后续切片评估。v0.2.0 不承诺一开始建立全盘实时索引；索引首次建立由用户显式刷新，文件操作成功后会为更新索引而重新扫描，避免启动或后台 watcher 扫描影响专注软件。

### 5.3 P2：录音与语音转文字

P2 是 v0.2.0 的后续能力，可按 Provider 和 Windows 权限准备情况在 `v0.2.x` 小版本发布。它不阻塞 P0 主路径和 P1 的文件 / 下载闭环。Phase 5 的首个 slice 只承诺 Windows 本地录音和 Inbox 回流；录音后转写必须作为单独的 Provider / local model slice 评审，避免在未确认隐私和设备边界时把音频发送到网络。

| 能力 | v0.2.0 最小范围 | 验收口径 |
|---|---|---|
| 录音（Phase 5 首个 slice） | Windows 默认麦克风；快速开始 / 停止；暂停 / 继续；`48 kHz / mono / 16-bit PCM WAV` 进入 Inbox；记录标题、时间、来源和设备；显示录音中 / 麦克风占用状态 | 录音可在任意普通桌面场景开始和停止，关闭窗口不会丢失已完成文件；不会静默录音；权限、设备占用和写入失败有可理解反馈 |
| 语音转文字（后续 slice） | 录音完成后按 Provider / 本地模型适配器转写；保留音频原件、文本和可选时间戳 | 转写失败不影响音频保存；结果可写入笔记并可再次处理；发送前显示目标 Provider 和隐私确认 |

语音转文字 slice 已于 2026-10-19 按 [ADR-0008](./decisions/ADR-0008-voice-transcription-and-relay.md) 实现：首个 Provider 复用本机 Relay（OpenAI 兼容 `/v1/audio/transcriptions`），`TranscriptionTransport` trait 为后续本地模型 / CLI Provider 预留；发送前的目标 Provider 与隐私确认为硬性要求。自动化验证已完成，Windows 打包态与真实 Provider 转写仍待人工验收。

实时转写、说话人识别、复杂音频编辑和多轨处理留到后续版本。

## 6. 统一动作契约

新能力必须通过 action registry 或其明确的适配层进入 Launcher，至少具备以下字段：

- `id`、`title`、`category`、`description`。
- `inputs`：支持的上下文类型、是否必需、权限要求和参数 schema。
- `outputs`：剪贴板、笔记、文件、通知或下一个动作。
- `execute()`：进行中、成功、失败、取消四种状态；失败包含用户可理解的错误和可重试性。
- `recent` / `favorite`：不把具体页面状态当作动作历史。
- `source`：builtin、script、provider 或 local service，便于审计和禁用。

统一的附件模型至少应能描述 `image`、`file`、`audio`、`transcript`、`link` 和 `text`，并保留来源、创建时间和关联 Inbox 项。该模型先服务本地存储，不引入云同步承诺。

## 7. 视觉与主题需求

### 7.1 方向

采用“可读的桌面玻璃工作空间”作为 v0.2.0 视觉方向。用户提供的参考图体现了以下语言：冷色浅蓝灰底、半透明模糊侧栏、轻边框、低对比阴影、编辑器式布局和悬浮工具栏。参考的是层次和材质关系，不复制具体品牌、图标或布局。

### 7.2 设计要求

- 建立统一 design tokens：背景、表面、玻璃层、边框、文字、强调色、状态色、阴影、模糊、密度和圆角。
- 明亮玻璃主题优先；暗色主题沿用同一 token 结构，作为可选增强。
- 玻璃层必须有不透明 fallback，在系统不支持模糊或窗口性能不足时保持可读。
- 主要内容区保持足够不透明度，不能为了“透”牺牲文字、选区和输入框的对比度。
- 统一处理 hover、focus、selected、disabled、error、loading 和拖拽状态。
- 去除页面级暖黄色 / 米色硬编码；笔记内容可以保留用户自定义颜色，但不应决定应用主题。
- Manager、Launcher、Quick Note 和后续捕获窗口使用同一套表面、边框和间距语言。
- 主题迁移按组件分批完成，先建立 token，再迁移页面，避免逐页继续新增颜色。

### 7.3 可用性验收

- 键盘焦点可见，文字与主要背景达到可读对比度。
- 半透明背景下，编辑区、按钮和错误提示仍能被快速识别。
- 窗口缩放、Windows 高对比度或关闭透明效果后，布局不重叠，功能仍可用。
- 视觉层次服务于捕获、搜索和执行，不增加装饰性面板或无意义的卡片嵌套。

## 8. 非目标

v0.2.0 不包括：

- 社区插件市场、任意代码插件执行和在线安装生态。
- 云同步、账号体系、多端协作和远程数据仓库。
- 复杂 Flow 编辑器、条件编排和跨设备流程同步。
- 一开始就完成全盘实时索引或替代 Everything 的完整文件系统能力。
- 完整音频编辑器、实时字幕、说话人识别和专业录音棚功能。
- 绑定单一翻译或转写服务的不可替换实现。

## 9. 发布验收与指标

### 9.1 发布门槛

1. Launcher 的键盘 / 中键入口、排除软件和快捷键重录在 Windows 打包产物中可验证。
2. Snow Shot 外部动作至少覆盖已安装后进入截图界面、D 盘注册安装发现、用户自定义路径优先、MCP 未启用指引、bridge 缺失、未安装打开官方安装页及无效路径 / 启动失败反馈；P0 的 Inbox 捕获和选中文本翻译至少各有一条自动化或脚本化回归路径。
3. P1 的指定目录搜索和下载队列具备失败、取消、冲突和恢复测试。
4. P2 如果进入 `v0.2.x` 发布候选，录音失败时音频不丢失，转写失败可重试，结果能回到笔记；P2 本身不阻塞 `v0.2.0` 的 P0/P1 核心发布。
5. 主题 token 已覆盖 Manager、Launcher、Quick Note；关闭模糊效果后没有明显重叠或不可读文本。
6. `docs/roadmap.md`、本 PRD、实施计划和相关模块文档描述一致。

### 9.2 体验指标

首轮版本可通过本地匿名计数或手工记录验证以下指标，不要求接入远程分析：

- 从入口到完成一次捕获的步骤不超过 3 个主要交互。
- 最近动作和收藏动作在 Launcher 首屏可直接复用。
- 一次捕获不需要先决定分类；后续整理能在 Manager 中完成。
- 失败操作都能回答“为什么失败、还能怎么做”。
- 个人试用一周后，截图、翻译、快速笔记至少有一项成为稳定的高频入口。

## 10. 待确认事项

- Snow Shot MCP 是调用截图界面的可选集成，依赖用户在 Snow Shot 中显式启用；截图结果回流、OCR 和翻译联动仍需单独评估，不作为当前动作的依赖。
- 翻译首个 Provider 已确认复用本机 ScriptMgr Relay；EasyFlowHub 仅保存目标语言与模型，密钥和路由继续由 Relay 管理。录音首个 slice 不依赖 Provider、不上传网络；转写 Provider、是否支持本地 CLI 和隐私确认流程在后续 slice 单独决策。
- 文件索引默认目录和 Windows 权限提示的具体交互。
- 录音的清理入口和用户可见的中断文件恢复策略；默认格式、保存位置、麦克风权限提示及外部 Provider 发送边界已在 Phase 5 ADR 中确定首个 slice 的基线，转写上传仍需单独评审。

这些事项不改变 v0.2.0 的产品优先级，进入对应 Phase 的技术设计时再决策。
