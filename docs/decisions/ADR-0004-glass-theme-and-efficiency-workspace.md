# ADR-0004 毛玻璃工作空间与个人效率 Hub

- status: accepted
- date: 2026-10-16
- scope: v0.2.0 and later
- related PRD: [PRD-v0.2.0.md](../PRD-v0.2.0.md)

## 背景

EasyFlowHub 已从单纯的脚本管理逐步扩展为包含快速笔记、待办、Launcher、脚本和桌面能力的效率工具。当前页面仍有明显的暖黄色、米色和“笔记本”视觉倾向，无法清楚表达截屏、翻译、文件、下载和语音等更广泛的桌面工作流。

用户提供的参考图展示了冷色浅蓝灰背景、半透明模糊侧栏、轻边框、低对比阴影、编辑器式内容区和悬浮工具栏。我们采用它体现的材质关系和信息层次作为方向，不复制具体产品的品牌和界面。

## 决策

### 1. 产品体验采用“个人效率 Hub”模型

v0.2.0 围绕 `Capture -> Understand -> Retrieve -> Act` 组织需求。Launcher 负责当前上下文中的高频动作，Manager 负责整理、配置、审计和恢复，Hub 负责共享动作、Inbox、附件和反馈概念。

### 2. 视觉采用可读的桌面玻璃工作空间

- 明暗两套玻璃主题共享同一组冷色浅蓝灰 tokens；浅色主题适合日间工作，深色主题适合夜间和低光环境，用户也可以跟随 Windows 系统主题。
- 玻璃材质通过半透明表面、背景模糊、轻边框和柔和阴影表达层次。
- 内容区比装饰层更不透明，文字、编辑器、结果和错误反馈优先保证对比度。
- 所有材质、状态和密度通过 design tokens 管理，禁止在页面中继续散写主题色。
- 系统不支持模糊、用户关闭透明效果或性能不足时，自动降级为不透明表面。
- 暗色主题已与明亮主题一起交付，主题状态同步到 Manager、Launcher、Quick Note 和独立窗口；系统主题变化会实时反映到使用 `system` 模式的窗口。

### 3. 主题迁移采用渐进式策略

先建立 token 和组件状态，再迁移 Manager、Launcher、Quick Note、Settings 及浮层。笔记正文、截图标注和用户内容的颜色不被主题迁移覆盖。主题迁移不改变数据模型、Markdown 和附件路径。

### 4. 高频入口优先复用 Launcher 和鼠标中键

截屏、翻译、快速捕获、搜索、下载和录音都应通过 action registry 暴露到 Launcher。全局键盘快捷键继续支持重录和排除软件；鼠标中键作为默认推荐入口；托盘和 Manager 按钮作为备用入口。

## 影响

- 产品叙事从“笔记应用加脚本”变为“在当前桌面上下文中快速捕获、理解、检索和执行”。
- 需要新增统一的输入 / 输出 / 附件契约，避免每个功能单独设计回流方式。
- 主题重构会触及现有 Manager、Quick Note、Todo 和 Settings 样式，需要分阶段迁移和视觉回归。
- 玻璃效果带来性能、对比度和系统兼容风险，因此 fallback 是必需能力，而不是可选优化。
- v0.2.0 仍然不承诺云同步、社区市场、全盘索引、复杂 Flow 或专业音频编辑。

## 备选方案

### 继续使用暖黄色笔记主题

不采纳。它能表达快速笔记，但无法承载文件、下载、翻译、截图和语音等并列能力，也会让用户把产品理解为单一笔记工具。

### 直接复制参考软件的完整界面

不采纳。参考图只用于确认材质和空间层次；产品仍需要围绕 Windows 快速动作、Inbox 和现有 Manager 组织信息架构。

### 一次性重写全部页面

不采纳。一次性迁移会放大回归范围；token 化和分阶段迁移可以保持现有功能稳定，并在每个阶段验证可读性和性能。

## 验证

- 视觉验证覆盖 Manager、Launcher、Quick Note、Settings 和至少一个结果浮层。
- Windows 打包产物验证透明效果开启、关闭、高对比度和低性能 fallback。
- 自动化验证覆盖主题 token 绑定、状态 class 和窗口功能不受样式迁移影响。
- 用户试用验证截图、翻译、快速笔记和文件搜索是否能从同一入口完成。
